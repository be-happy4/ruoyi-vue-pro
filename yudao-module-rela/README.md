# 关系说明

中文语义下，关系本身包含了很多额外信息。
如堂表之分、亲疏远近、性别、婚姻状况等。
这些信息可以作为关系的属性，或者作为关系的衍生条件。

## 基于父母关系推导的关系网络

基于父母关系，结合性别、年龄等额外信息，基本可以推导出大部分中文亲戚关系称谓。
例如：

- A.sex='M' AND (A.父亲=B OR A.母亲=B) => B.儿子=A
- A.sex='M' AND (A.父亲=C AND B.父亲=C OR A.母亲=C AND B.母亲=C) AND A.birthDay < B.birthDay => B.哥哥=A
- A.父亲=B AND B.哥哥=C => A.伯伯=C

缺点是夫妻关系需要由共同子女来间接推导，如果没有子女，则无法推导出夫妻关系。

## 基于其他关系的可行性
我应该使用父亲母亲作为基本关系，还是直接用父母作为基本关系，而性别只是基本关系的额外属性，从而推导出具体的关系。这样基本关系似乎会更简单一些，但是性别属性相关推导出来的关系（称呼）会更加复杂


模型统一，现在是从头开始，摒弃一切包袱，长远考虑推导引擎的具体实现、如何规划基础关系、关系中的属性，来获得更高的效率或更便捷的用户体验，量化体现出不同方案的优缺点
